# ProprDB improvement TODO

The largest opportunities are correctness and architecture rather than
micro-optimizations.

## Highest priority

- [ ] Decide whether ProprDB preserves history or only latest state.
  - The README promises change-history preservation, but each object table and
    tombstone stores only the latest state. Intermediate edits made before an
    export are lost.
  - If history is a hard requirement, introduce an append-only change journal
    and treat the current per-type tables as materialized state.
  - Otherwise, clarify the goal and document that only the latest state is
    retained.
  - Evidence: [README.md](README.md#goals),
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go).

- [ ] Make compound mutations atomic.
  - Inserts and updates currently remove a tombstone before writing the live
    row, while deletes write a tombstone before removing the live row.
  - A failure between statements can leave missing or contradictory state.
  - Wrap each logical mutation in a transaction, or store live and deleted
    state together so conflict resolution is one conditional UPSERT.
  - Add failure-injection tests using aborting SQLite triggers at every
    statement boundary.
  - Evidence:
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go).

- [ ] Separate export creation from remote acknowledgement.
  - `WriteJSONL` marks each record synced immediately after writing it. A later
    writer or transport failure can suppress that record on retry even when
    the caller discarded the partial output.
  - Generate a batch plus checkpoint, then update `_sync` only through an
    explicit acknowledgement after durable delivery.
  - Add tests with a writer that fails after one complete record and verify a
    full retry remains possible.
  - Evidence:
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go).

- [ ] Enforce deterministic equal-timestamp behavior.
  - The documented contract says equal timestamps are idempotent and
    payload-equal, but imports currently overwrite on equality.
  - Treat semantically identical live data or identical tombstones as no-ops.
  - Return a typed conflict for different payloads or live-versus-deleted state
    at the same timestamp.
  - Test both arrival orders and repeated identical records.
  - Evidence: [README.md](README.md#high-level-design),
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go).

- [ ] Replace raw wall-clock timestamps with a monotonic allocator.
  - Go uses `time.Now().UnixNano()`.
  - Swift converts `Date` through `Double`, which readily produces duplicate
    nanosecond values.
  - Allocate timestamps atomically as at least
    `max(wall_clock, current_object_timestamp + 1)`, or introduce a persisted
    hybrid logical clock.
  - Test frozen clocks, clock rollback, imported future timestamps, concurrent
    writers, and rapid consecutive Swift writes.
  - Evidence: [rt/runtime.go](rt/runtime.go),
    [Runtime.swift](swift/ProprDBSwiftRuntime/Sources/ProprDBSwiftRuntime/Runtime.swift).

- [ ] Make `atNs` portable across JSON implementations.
  - Current timestamps are around `10^18`, above the exact integer range of
    common IEEE-754-based JSON implementations.
  - Emit `atNs` as a decimal string and temporarily accept both strings and
    exactly representable integer numbers.
  - In Swift, reject booleans, fractions, overflow, and underflow instead of
    coercing through `NSNumber.int64Value`.
  - Add cross-language tests for current 19-digit timestamps and integer
    boundaries.
  - Evidence: [README.md](README.md#object-model),
    [Runtime.swift](swift/ProprDBSwiftRuntime/Sources/ProprDBSwiftRuntime/Runtime.swift).

## Generator correctness

- [ ] Support multiple proto files in one Go package or Swift module.
  - Every generated file currently emits package-level `DBTX`, `CRUD`, and
    wrapper declarations, causing redeclaration errors.
  - Emit one deterministic aggregate wrapper per output package/module, or
    namespace wrappers per source file and provide an explicit composer.
  - Add a two-file generation test that compiles both Go and Swift outputs.
  - Evidence:
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go),
    [internal/proprdbgen/swift_generator.go](internal/proprdbgen/swift_generator.go).

- [ ] Implement SwiftProtobuf-compatible symbol naming.
  - Current Swift naming is inferred from Go names and package capitalization.
  - It does not correctly handle nested messages, `swift_prefix`, underscored
    or mixed-case packages, reserved names, keywords, or presence-name
    collisions.
  - Build names from descriptors using SwiftProtobuf-compatible rules.
  - Compile-test nested types, `swift_prefix`, reserved identifiers, keywords,
    acronyms, and `has*` collisions.
  - Evidence:
    [internal/proprdbgen/swift_generator.go](internal/proprdbgen/swift_generator.go).

- [ ] Define valid SQLite encodings for every projected scalar kind.
  - Swift currently cannot bind generated `Int32`, unsigned integers, or enum
    values directly.
  - SQLite INTEGER and Go `database/sql` cannot represent the upper half of the
    protobuf `uint64` and `fixed64` ranges.
  - Generate explicit conversions for supported kinds and define a lossless,
    query-order-preserving encoding for full-width unsigned values.
  - Until such an encoding exists, reject unsupported projections during code
    generation.
  - Include the storage encoding version in projection schema metadata.
  - Test every scalar kind, optional absence and presence, unknown enum values,
    embedded NUL strings, and unsigned integer boundaries.
  - Evidence:
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go),
    [Runtime.swift](swift/ProprDBSwiftRuntime/Sources/ProprDBSwiftRuntime/Runtime.swift).

- [ ] Reject projected fields that collide with fixed columns or generated
      symbols.
  - External fields named `id`, `at_ns`, or `data` currently produce duplicate
    SQLite columns.
  - Validate message names against generated `CRUD`, `DBTX`, row, and table
    declarations.
  - Report these errors during generation rather than during database
    initialization or compilation.

## Schema migration

- [ ] Compare complete projected-column definitions during initialization.
  - Initialization currently checks only whether a column name exists.
  - Optionality changes retain incorrect `NOT NULL` constraints, type changes
    retain old affinity, and removed columns remain indefinitely.
  - Compare affinity, nullability, defaults, and encoding version.
  - Rebuild incompatible tables transactionally through a shadow table and
    rollback cleanly on failure.
  - Test required-to-optional, optional-to-required, type changes, column
    removal, data preservation, and migration failure.
  - Evidence:
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go).

- [ ] Separate projection metadata from index metadata.
  - Index signatures are currently part of `ProjectionSchema`.
  - Adding, removing, or merely reordering indexes therefore causes a complete
    protobuf decode and reprojection of every row even though indexes are
    reconciled independently.
  - Store canonical projection encoding metadata separately and ensure
    index-only changes perform zero row updates.

- [ ] Make reprojection transactional and bounded-memory.
  - Both generators buffer the complete table and update one row at a time.
  - Page through rows, reuse prepared statements, and perform the migration in
    one transaction.
  - Ensure cursors are closed on every error path.
  - Benchmark representative large payload tables.

## Sync and storage performance

- [ ] Remove N+1 sync queries.
  - Export currently selects and decodes every live row, then queries
    `SyncNeedsSend` and updates `_sync` once per emitted object.
  - Import performs separate live-row, tombstone, sync, and mutation queries
    for each record.
  - Filter export candidates with a SQL `LEFT JOIN` or `NOT EXISTS`, stream
    records, and batch acknowledgement updates.
  - Batch imports in transactions using prepared statements.
  - Evidence:
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go).

- [ ] Remove the single-connection tombstone export deadlock path.
  - Tombstone export performs nested queries and writes while its result cursor
    remains open.
  - With one available database connection, the nested operation can wait
    indefinitely.
  - Close or buffer the cursor before acknowledgement updates.
  - Add a sync-enabled tombstone test with `SetMaxOpenConns(1)`.

- [ ] Add streaming Swift JSONL APIs.
  - Swift currently materializes all selected rows and builds the complete
    export as one `String`.
  - Input similarly splits a complete in-memory `String`.
  - Add byte-stream or asynchronous sequence APIs and retain String
    conveniences only for small payloads.
  - Verify bounded memory with large, mostly-synced databases.
  - Evidence:
    [internal/proprdbgen/swift_generator.go](internal/proprdbgen/swift_generator.go),
    [Runtime.swift](swift/ProprDBSwiftRuntime/Sources/ProprDBSwiftRuntime/Runtime.swift).

- [ ] Simplify unknown-type storage.
  - Replaying an identical unknown record currently violates the
    `(type_name, id, at_ns)` primary key.
  - Parked records are not exported, so an older client cannot forward them.
  - Global compaction repeatedly scans the complete unknown table.
  - Store the latest state through a timestamp-conditional UPSERT keyed by
    `(type_name, id)`, or retain all records in the append-only journal if
    history preservation is selected.
  - Apply normal conflict resolution when draining into a newly known type.
  - Test duplicates, out-of-order records, forwarding through an older client,
    and replay against newer local state.
  - Evidence: [rt/runtime.go](rt/runtime.go),
    [internal/proprdbgen/generator.go](internal/proprdbgen/generator.go).

- [ ] Run global initialization work once per CRUD wrapper.
  - Every table currently recreates all core tables and recompacts unknown
    records.
  - Ensure core tables and compact unknown records once, then initialize and
    drain individual types.

- [ ] Correct or rename `DiskUsageBytes`.
  - It currently measures payload lengths rather than actual SQLite disk usage
    and excludes indexes, row metadata, and page overhead.
  - Rename it to payload or estimated bytes, or use SQLite `dbstat` for
    allocated bytes.
  - Combine count and payload aggregation where possible.
  - Evidence: [rt/runtime.go](rt/runtime.go).

- [ ] Benchmark storage layout before changing primary keys.
  - Compare the current rowid plus `TEXT PRIMARY KEY` layout with
    `WITHOUT ROWID` and 16-byte UUID storage.
  - Include secondary-index size, lookup time, insertion time, and migration
    cost.

## Swift runtime hardening

- [ ] Replace manual transactions with a scoped `withTransaction` API.
  - `finished` is written but not enforced, abandoned transactions are not
    rolled back, and a transaction object remains usable after completion.
  - Automatically commit on success, rollback on thrown errors, invalidate
    completed transactions, and log fallback rollback failures from `deinit`.
  - Test dropped, thrown, double-finish, and use-after-finish transactions.
  - Evidence:
    [Runtime.swift](swift/ProprDBSwiftRuntime/Sources/ProprDBSwiftRuntime/Runtime.swift).

- [ ] Prevent `SQLiteRow` from escaping its statement lifetime.
  - A row currently stores the statement pointer directly. Advancing or
    finalizing that statement can make a saved row observe later data or
    access invalid memory.
  - Materialize row values, make row access non-escapable, or hide the
    low-level API behind scoped decoding.

- [ ] Introduce actor-isolated database execution.
  - Swift 6 mode is enabled, but the mutable SQLite handle has no actor
    ownership.
  - `SQLITE_OPEN_FULLMUTEX` protects individual SQLite calls, not compound
    operations or transaction ownership.
  - Add an actor-owned async facade and make value results explicitly
    `Sendable`; do not use `@unchecked Sendable` for the raw handle.
  - Add strict-concurrency compilation and concurrent transaction
    serialization tests.

- [ ] Handle every SQLite setup and cleanup result.
  - Check busy-timeout and extended-result-code setup.
  - Do not silently ignore `sqlite3_close` or `sqlite3_finalize` failures.
  - Add a `SQLiteRows` deinitialization fallback that logs finalization errors.

- [ ] Bind SQLite text and empty blobs explicitly.
  - Text binding with a length of `-1` and retrieval through `String(cString:)`
    truncates valid embedded-NUL strings.
  - A nil pointer for empty `Data` can bind SQL NULL instead of a zero-length
    BLOB on some platforms.
  - Bind explicit UTF-8 byte lengths and use `sqlite3_bind_zeroblob(..., 0)`
    for empty data.
  - Test empty protobuf payloads and NUL-containing projected strings.

- [ ] Raise the Swift package minimum to iOS 26.
  - Both runtime and test packages currently declare iOS 18 despite the
    project policy.
  - Validate an iOS 26 build after updating the manifests.

## API design

- [ ] Add caller context to generated Go APIs.
  - Generated methods create `context.Background()` internally, preventing
    cancellation, deadlines, and tracing during lock waits, large selects,
    sync, and migrations.
  - Make context part of the primary API or add `Context` variants with
    compatibility wrappers.
  - Test cancellation before and during selection, migration, import, and
    export.

- [ ] Clarify that `WriteJSONL` mutates sync state.
  - The current name appears to describe serialization even though a non-empty
    remote changes `_sync`.
  - Prefer explicit prepare/acknowledge terminology if acknowledgement is
    separated from export.
